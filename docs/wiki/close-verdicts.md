# Close Authoring, Verdict Classes & Review Doors

How a run's *done* gets declared, judged, and finally disposed of — from the authored close through to the human at the door.

## 1. The verdict classes, current state

**The classes are `green` + `soft-green`. `hitl` is retired** (Addendum v1.71). Originally the design had three classes on a user-picked radio — green / soft-green / hitl (PRD v1.57 §1, restoring the 2026-07-21 locked design) — but after the first live hitl proving loop, hamr retired hitl outright: *"checkers are subjective human experience that they should grade for"*, *"hitl should be at every step, then do it in regular chat"*, *"it's hard to apply deterministic flow on a probabilistic throughput"* (PRD.md:5151-5159). The forcing evidence was a second authoring run that, lacking any kind able to count documentation, reached for strict typecheck as a self-described "intentional calibration" proxy — exactly the fake-hard verdict class F87 exists to prevent (PRD.md:5161-5166). Hitl was not retired for a defect — its first live firing executed correctly end to end — it was retired for what it demands of a composer and of a person (PRD.md:5140-5142, 5261).

`soft-green` stays **declared-but-locked** until its judged floor is built and calibrated (PRD.md:5168-5169); v1 of close-authoring admits only `green`, with any soft-green/hitl pick returning an honest counted refusal on the `request-red` path (PRD.md:3829-3832).

## 2. Close authoring: the declaration model

The last authored layer un-authors: instead of a hand-written script (`scripts/u-*-close.mjs`), a chat interview's answers are composed by an LLM into a **DECLARATION** over operator-owned stage KINDS — never code, no escape hatch (D1–D3) (PRD.md:3563-3566).

- **The verdict class is a USER CHOICE, not derived.** This supersedes the close-authoring record's D4 ("verdictType is DERIVED from the answers"): the user knows whether their *done* is machine-checkable, needs judgment, or needs a person — a derivation can't infer that from answers given before the question is asked (PRD.md:3817-3827, 3973-3977).
- **The picked class is a PROMISE the composer must keep.** Composition may only use kinds at or below the picked class; a declaration whose computed ceiling exceeds the pick is an honest red naming which kind raised it — never a silent upgrade (the fake-hard verdict class) and never a silent downgrade (PRD.md:3834-3849).
- **The interview re-keys from GENRE to VERDICT CLASS**: three frozen question sets (green / soft-green / hitl, now green / soft-green) replace one set per genre, because genres are an unenumerable long tail while verdict classes are exactly three or two (PRD.md:3852-3865). Genre understanding moves into the LLM's composition over the kind catalogue instead of the interview (PRD.md:3860-3864).
- **The D5 mandatory guard battery keys to the VERDICT CLASS**, not to a genre label or per-kind — a green job carries the green battery whatever genre it came from, because a battery exists to police the class of dishonesty the class of verdict admits (PRD.md:3866-3878). Tool-specific guard fills (which suppression patterns, which language spellings) still resolve at composition time (PRD.md:3880-3886). Softgreen carries **no battery of its own** — it inherits green's verbatim (PRD.md:5372-5379).
- Mandatory genre guards are shown-and-fixed (D5, the F87 antidote); the user signs the whole hash (D7); nothing LLM-judges the close — only the validator, precheck, and seed-verdict read, then the signature (D9) (PRD.md:3567-3569).
- **D11–D13:** the authoring scout emits a facts object and the authoring call stays toolless; the close stores the COUNTING RULE, never a number (repeated jobs re-measure at their own seed); v1 is one genre, interview-confirmed, with honest refusal via `request-red` (PRD.md:3574-3578).
- A safety floor sits under declared commands: a deny-floor of dangerous commands is required (a straight block or human gate, never silent allow), and **the agent creates a new branch before touching any code — a hard rule, no exceptions**, named with a meaningful slug like `bareloop-typecheck-fix` (PRD.md:3890-3907). This narrows blast radius; it is explicitly not a sandbox — network/OS-user permissions, env exposure beyond the strip list, and resource use (CPU/memory/disk) remain unbounded by anything here (PRD.md:3909-3929).
- **The close is never bounded in time.** No wall or hard timer chops a running close; a close in flight when a deadline trips runs to completion and keeps the grade it mints (the F45 money rule generalized to time). A STUCK close is instead caught by **signs of life** — the per-stage `timeoutMs` is a stuck-backstop the operator owns (may only tighten, never widen), not a duration budget (PRD.md:3931-3950). A measuring command that crashes must fail loudly as could-not-run, never render as a zero (PRD.md:3952-3955).

## 3. The staged close: red-set and grading rules

A staged close has N `gapKeep` patterns, one per stage, and the stage that renders the verdict varies attempt to attempt.

- **Layer R's red-set is the FAILING STAGE's, per attempt** — the detector refuses to compare red-sets across a stage change, since a different wall of the close is a different failure and repetition isn't provable (PRD.md:1988-2000). The rejected alternative — one union `gapKeep` for the whole run — was measured to false-positive on a real corpus where two close stages shared 7 of 12 byte-identical kept-line templates (PRD.md:2002-2012).
- **The grading stage is not lendable.** All shipped specs set `offer:false` on their final `verdict` stage so the close's own grade never appears in the agent's derived check menu; kept as a per-spec flag, not a schema rule, with a test that reds any spec offering its own last stage (PRD.md:2029-2043).
- **A declared count stage carries the LINES it counted**, not just a number — "8 match(es)" with no file or line is F28's rule (the close's output format is part of the contract) reappearing in the authored-close executor. Only the kept lines (the ones the count is made of) are echoed, riding the existing `gapKeep` prefix and `GAP_LINE_CAP`; the identical job stalled at 8 with count-only gaps but converged 67→8→1→0 with the lines (PRD.md:4125-4155).
- The close child's environment strips credentials before running worker-authored code: `CLOSE_ENV_DENY` removes known names (`ANTHROPIC_API_KEY`, `AWS_*`, etc.) plus any name-shape match (`_API_KEY`, `_SECRET`, `_TOKEN`, `_PASSWORD`, `_CREDENTIAL(S)`), extended later with real spellings like `PGPASSWORD`, `STRIPE_KEY`, bare `TOKEN`/`SECRET` (PRD.md:2392-2443). This is exposure reduction, not a sandbox — the operator's OS-user permissions and network access remain fully in reach of worker-authored code (PRD.md:2418-2433).
- Both signing surfaces show the goal and the judged/close stages as ONE reading: `run-u`'s approval gate now names every close stage under the goal, and `run-author`'s readout gains the goal rendered from the resolved (hashed) spec — because F87's law (the goal must state everything the close will judge) has exactly one defence: the signer reading both halves at once (PRD.md:4301-4321). The arbiter's own books (`.smoke`, `.litectx`, gate audit) are now REGISTERED in the worker's persona prompt rather than discovered by three costly denied reads (PRD.md:4327-4342).

## 4. Verdict routing fixes (F32 lineage)

- **`gate-red` is extinct as a mintable terminal.** A deny streak (the worker probing the arbiter's own books, correctly denied by the fence) now bounds the ATTEMPT, not the RUN: the attempt ends, the close judges the partial work, the gap feeds forward, and the loop continues — joining `max_turns` in the bounded-attempt lane. This is F32's crash-attribution rule (a stop after gate-audited writes is `worker-crash`, non-terminal) applied to the most benign member of that class: a fence denial is the system working as designed (PRD.md:4095-4123).
- **W-2 closes over the sibling terminals.** Every variance and cap-halt terminal now re-reads the clock through one shared emission site before minting its name, because the terminal's name gates resumability (`RESUMABLE_HALTS` admits `cap-halt`/`wall-halt` only); a stop past the wall never funds a replan draft on any trigger; both allowances exhausted reports the money cut (`cap-halt` wins over `wall-halt`) (PRD.md:4157-4179). A resume may derive `wall-halt` from a recorded `step-red` only when the run's own spine shows the wall crossed first, announced with a banner (PRD.md:4180-4182).
- The drafter now carries the no-shell law directly (a prompt register, deliberately not a regex, to avoid false-redding the operator's own signed goal text) after a replan told a shell-less worker to run `npx tsc` and it burned a whole step hunting errors by hand instead (PRD.md:4190-4206).
- A worker-crash attribution carve-out (F32) distinguishes a crash after audited writes (`worker-crash`, non-terminal, retried) from an instrument crash at precheck or with zero writes (still forbidden-zone, escalates) (PRD.md:951-960).

## 5. Softgreen: the judged floor

Softgreen's shape is **LOCATE + DECIDE**, borrowed only as shipped primitives (bare-agent 0.36 `judge`/`calibrate`/`judgeToAnnotation`, bareguard 0.13's annotation drain) — bareguard's own judge A/B was a POC that never shipped, so the `decide()` rulebook is written fresh in bareloop, arbiter-owned (PRD.md:5212-5216).

- **The judge never utters a verdict.** Pinned `claude-haiku-4-5`, it extracts facts with quotes from the authoritative artifact (the real diff, never the worker's summary); a deterministic, arbiter-owned `decide()` renders per-item pass/fail, first-red-wins. `judgeVerdict` is injectable, `judgeLocate` is not — unsure = red, decisive binary only (PRD.md:5217-5222).
- **The rubric card** comes from interview Q6 ("what separates a pass from a fail?"), compiled into extractable items D5-style — LLM proposes, signer signs, a card change is a re-sign. The judge only catches violations of stated card items; omissions and lies needing an oracle fall to the review door (PRD.md:5223-5229).
- **Calibration** comes from Q7 (one pass example, one fail example): a frozen set the whole pipe (extraction + `decide()`) must grade correctly, itemized, before the close is signable; a judge-model bump forces recalibration (PRD.md:5230-5234).
- **Composition:** mechanical stages first, judged stage after, first-red-wins; the judged stage is `offer:false`, metered from the same wallet, and skips the seed-verdict read because its bar comes from calibration — this is what makes a resume-tailoring job expressible without a manufactured mechanical shadow (PRD.md:5235-5239). The softgreen interview is seven questions: green's five plus Q6 and Q7 (PRD.md:5240-5241).

**Thresholds, ruled (2026-08-18):**
- Calibration set size is **10** ("go build 10, we could double later" — doubling later explicitly allowed; any size change stays operator territory) (PRD.md:5346-5354).
- Calibration floor is **10/10, zero reds** — the whole pipe must grade all 10 signed cases correctly, itemized; no partial floor, no best-of (PRD.md:5356-5362).
- Bare-agent's **5-style INJECTION_BATTERY** runs alongside the 10 cases and all 5 must resist or calibration fails (PRD.md:5364-5370) — later **adapted** rather than run as-is, since a locate-only judge has no `shouldBreak` verdict for the battery's gold to grade; the same 5 attack styles are re-aimed so a case passes only if the extracted facts are unaffected (PRD.md:5644-5651).
- Judge bounds confirmed ("keep the caps"): `JUDGE_MAX_TOKENS=4000`, `JUDGE_ATTEMPTS=2` (measured ~1-in-6 malformed JSON at haiku-4.5), `MAX_JUDGED_PATHS=8` (PRD.md:5653-5658).
- **Pure-judged closes were made signable** in this rung: the D9.3 signing gate (≥1 work-stage red at seed) previously blocked a close whose only work stage is `judged-floor`. For a judged-only close, the calibration gate (10/10, zero reds) now plays the role the seed-red check plays for mechanical stages, proving the close can fail — mechanical-stage closes are unchanged (PRD.md:5660-5673).
- **The judge tier joined the signature** on release: `calibration.judgeModel` is stored inside the spec so `jobSpecHash` covers it by construction — a model bump flips the hash, kills the signature, and forces re-sign + recalibration; an absent stamp is not a runtime stop since a signed spec can't reach a run without one (PRD.md:5734-5741).

Nothing here claims `judged-floor` works on a paid run — the calibration gate exists and is enforced, but softgreen has never rendered a live verdict (PRD.md:5772-5773, 5677, 5393-5395).

## 6. Review doors: accept / rerun / pause

The pause machinery built for the retired hitl slice was not deleted — it was **re-homed one level out**, from a stage inside the close to a door at the end of **every** run, green and softgreen alike (PRD.md:5177-5180). The governing law: *"it's important not to change the loop self verdict"* — the close mints the verdict, the door only records a disposition (PRD.md:5182-5184).

- **The three doors are `accept` / `rerun` / `pause`** — `cancel` was deleted outright, not renamed or aliased, because *"pause can resume — that would be more honest"* and rerun already implies dislike-and-retry. `HUMAN_DECISIONS` makes cancel inexpressible rather than merely rejected (PRD.md:5280-5283).
- **Pause spends nothing** — no worker round, no fix loop, no allowance moved, in any state including below the wall-exhausted gate — and does not consume the one-shot rerun allowance; it mints the ordinary `hitl-pause` checkpoint terminal and resumes at the start of the last step (PRD.md:5285-5291, 5380-5384).
- **The 60-day TTL is the cancel case**: an unresumed pause simply expires, producing cancel's old end-state (abandoned, branch untouched, nothing graduates) for free, while someone who returns keeps the work already paid for (PRD.md:5298-5303).
- **A rerun is a fresh engagement**, never a replay: it authors its own money and time, never scavenging the corrected run's leftover wall (the ledger carries cumulative-so-far and this-engagement as separate counters) (PRD.md:5196-5200). It also never re-runs the same plan or asks the same question — the signer's words enter the next plan draft as the gap, and a different plan across legs is not evidence of a worse plan, given this programme has measured two cold runs of one job producing two different working plans, both green (PRD.md:5718-5727).
- **A halt records full state**, including any pending human decision — a resume re-enters the fix loop with it, never the ask (F102's cure) (PRD.md:5202-5206).
- **Green's door stays opt-in** (`--review-door` / `reviewDoor:true`; `REVIEW_DOOR_CLASSES=['soft-green']`) — a mechanical green has already said everything a person would be asked to confirm, and an always-on door there is the same rubber-stamp reading that retired hitl. The rerun door remains the refute lever for a signer who disagrees later (PRD.md:5707-5716).
- **On softgreen**, in the signer's own words: *"accept on softgreen = green, rerun = refuse and try again, pause = ttl for 60 days"* (PRD.md:5696-5697). `accept` is the person's act on the verdict already minted, and it is also what releases the quarantined learning credit (PRD.md:5699-5701, 5190-5192). The U runner now actually writes that credit-release row through the same seam `runReuse`'s greens use — storage only; reuse selection and promotion stay parked on the reuse rung (PRD.md:5742-5749).
- **One door hole was named and left** — a green-class run with a `--registry` minted no row, so `accept` against a registry refused `credit-not-held` (PRD.md:5751-5759). **Closed 2026-08-30** (hamr, PRD open item #16): a green-class run now mints its row at run end, born released (a machine proved it, no credit to quarantine); soft-green is unchanged (held → accept releases).

## 7. What's not claimed

No claim that rerun conversion works live (delivery proven, conversion unproven — F102/F103 surfaced live and were fixed as primitives, not proven under fire) (PRD.md:5147-5150, 5258). No claim `judged-floor` works on a paid run — softgreen has never rendered a live verdict (PRD.md:5259-5260, 5772-5773). No claim the hitl machinery was ever defective — it executed correctly on its one live firing before being retired for what it demanded, not what it did wrong (PRD.md:5261). The arbiter itself never moves in any of this: no budget, cap, fence, wall, or merge semantic changes across the whole verdict/door rework (PRD.md:5262, 5775-5776).
