Audit tab: fix part

Fix part in the Audit tab, shaped like the step try view; real data from run mvtatlxw (pulselog-strict-live-3). The fix part has 4 tries over 8 close checks: the opening close, then 3 fix iterations, the last one cut off when the provider dropped the connection. Five ways to draw it, same data, same tokens and glyphs as the panel.

Data notes.
  • Real panel wording is kept: the close's command-exit checks #3 (tsc exit 0) and #6 (npm test exit 0) now read "does \"npx tsc --noEmit --strict\" exit clean?" and "does \"npm test\" exit clean?" (Task 2 wording).
  • Try 1 is the opening close (no model call); tries 2 to 4 are fix iterations 1 to 3. Try 4 ended with no verdict (provider-red); its wording in the try line is lab-written, the panel has no words for it yet.
  • Check questions were hand-copied from the panel's stage wording for this signed close; gap lines are the verdict's own close lines, as the panel's reasons list cuts them.
  • Rounds tables use the run's gate-audit rows (model call rows, then its tool calls); 20 rows a page, load more.

F — grid for steps, errors like D

Why: One grid look for every part; click a ✗ to read its errors like D.

Key differences
  • Variant B's grid on step parts too: a green first-try step (typedef-and-helpers), a step with a red try (zero-target-errors) and the fix part.
  • Under each grid an "errors" list: one row per failed or verdict-less try (caret, try N, first failed check #K with "+J more checks", first error line ellipsised, faint "(+M more)"). All-pass tries get no row; a part with no failed try shows no list.
  • Rows are buttons and fold independently (several can be open); an open row shows the first 8 lines per failing check (sub-heading when several) and a "+N more lines" toggle. A grid red cell opens and focuses its row. The ? row (no verdict) is plain text, not clickable. On load only the last red try's row is open per part. Rounds fold per try under the list.
  • Check #3 carries a faint marker where the panel's wording duplicates #6 (lab-only marker).

A · mirror

Why: the fix part reads exactly like a step, so nobody learns a second view.

Key differences
  • Same try line, numbered checks in run order, folded "the N reasons", rounds fold per try.
  • Checks that never ran are listed as "· not run" (the fix close declares 8, first red wins).
  • Cost, time and calls sit in the rounds fold summary, since a fix try pays for its own model calls.

B · check grid

Why: the question a fix part asks is "which check kept failing, and did it move?", which a grid answers at a glance.

Key differences
  • Rows are checks, columns are tries; click a red cell for that try's gap lines, which open under the row.
  • Cost, time and calls per try in the footer rows; rounds tables fold under the grid per try.
  • Departs from the step view: no try lines, no per-check wording like "(N reasons)".

C · compact

Why: a fix loop can run many tries; one line each keeps the part short until you pick one.

Key differences
  • One line per try: result, thinking, the first failing check, cost, time. Click to open A's detail.
  • The line names the failing check (its question), not the gap text; the gap sits in the folded reasons.
  • Everything folded by default, so the part is 4 lines tall closed.

D · first-red focus

Why: first red wins, so the one check that decided the try is the only one that matters; show it open.

Key differences
  • Each try shows only the check that rendered the verdict, its gap lines open (scrolls inside its own box).
  • The other checks are one summary, "2 passed, 5 not run", that unfolds to the list.
  • Rounds stay folded. Loses the full numbered list at a glance; keeps it one click away.

E · step and fix unified

Why: shows one try block drawn the same everywhere, a plan step above the fix part.

Key differences
  • The step (zero-target-errors, 2 tries, same run) and the fix part use the same function; same try line, same fold.
  • Both parts carry the tools tally line; the step has 2 checks per try, the fix close has 8.
  • Nothing special-cased for fix: the only fix-only text is the "opening close" label on try 1.
