(a) Run page of a green job, not scheduled Run tab
phone (390px)
  • Schedule run is the LAST button of the Run tab's one action row, after Reuse workflow (fwd: right after Run again, index.html:2353-2358).
  • It shows only when the server says the job can take a schedule: a real green with the job's current workflow key; a rubric job also needs your Accept once. No good run = no button.
  • A click starts and signs nothing and its label never changes. It opens the Chat card in Reuse mode with the When field (box b).
(b) The schedule card Chat tab, Reuse mode. Try it: change When, click the button twice
phone (390px)
  • The boxes you can change: Inputs, Destination, When, Cap $, Time cap. Everything else is the signed job, greyed. The Model is the green run's.
  • When sits between Destination and the caps (fwd: between Inputs and Cap, index.html:998-1019). Day box only for "Every <day>"; time box for the three clock kinds; path box only for the two file kinds.
  • ONE main button. When unchanged it is the Reuse card's own Sign & run. Changed to a schedule: Sign schedule. Click 1 ($0, signs nothing): Confirm: every day at 09:00. Click 2: signed; the card clears to the empty New job card and the button is dead for 1.5 s. Nothing runs. No Run button is offered after.
  • On a scheduled job the first When option reads Cancel schedule; choosing it makes the button Cancel schedule, then Confirm: cancel schedule.
  • Edit a When box between the clicks and the hash is dropped: the button goes back to Sign schedule.
(c) Run page of a scheduled job Run tab
phone (390px)
  • SCHEDULED / NEXT block at the top of the Run tab (fwd index.html:1156-1157, 2223-2240), above the action row. NEXT goes red when the month is used up.
  • Cancel / modify schedule takes the place of Schedule run, last in the row, on every run of the job. Same door: it opens the card in (b) showing the current schedule.
  • A run waiting for your Accept does not hold the next scheduled run (RULED T7); the NEXT line says so.
